Overview

Rendering intent is separated from rendering execution. Each frame, game and UI code produces a flat list of DrawCmd structs. That list is sent asynchronously to RendererServer, which owns SDL and executes the actual draw calls through DrawCmdInterpolator — interpolating between the last two command-list snapshots for smooth motion at any display rate.

  • Smooth display at any refresh rate. Two command snapshots allow lerp between logic ticks.
  • Determinism / rollback friendliness. DrawCmd is a plain value type — serializable, diffable, replayable.
  • Resource indirection. Textures and font glyphs live entirely in the server; the client holds opaque UInt64 IDs. Glyphs are loaded by UID just like images — no new DrawCmd type needed.

public override func draw(time: UInt64) throws {
    totalDrawTime += time
    renderClient.clearCommands()                        // 1. reset list
    drawable?.draw(time, renderClient)                    // 2. game draws
    if let view = rootView {
        let ctx = UICommandContext(client: renderClient,
                      fontProvider: imageManager,
                      rttAllocator: renderServer)
        try view.draw(ctx, view.frame)                    // 3. UI draws
    }
    renderClient.sendCommands()                          // 4. async send
    renderServer.drawingInterpolator.draw(totalDrawTime - 100)  // 5. present
}

RTT note. The current .rtt DrawCmdType has no payload — sub-commands are captured but discarded. A future implementation would use .rtt(commands: [DrawCmd], targetResourceId: UInt64) targeting the allocated atlas region. Glyphs inside RTT work without changes once their IDs are registered. RTT frames are not stable across logic ticks; the interpolator would need to treat RTT targets as non-lerp-able. RTT design is deferred.

Interpolation Detail

Buffer swap — receiveCmds()

// DrawCmdInterpolator.swift:43–67 — simplified
func receiveCmds(_ list: [DrawCmd]) {
    let imageOnly = list.filter { $0.type.isImage() }

    _lastCmdList  = _futureCmdList
    _lastAllCmds  = _futureAllCmds

    _futureCmdList = IndexedOrderedList(imageOnly, keyPath: \.animationId)
    _futureAllCmds = list.sorted { $0.z < $1.z }
}

Lerp draw — draw()

// DrawCmdInterpolator.swift:69–143 — simplified
func draw(_ time: UInt64) {
    var resolvedPositions: [UInt64: Rect<Int>] = [:]

    for cmd in _futureAllCmds {                     // sorted by z
        switch cmd.type {
        case .image(let resourceId):
            let prev         = _lastCmdList[cmd.animationId]
            let interpolated  = prev.map { cmd.lerp($0, time) } ?? cmd
            let absolute      = resolvedDest(interpolated.dest,
                                    parentId: cmd.parentAnimationId,
                                    positions: &resolvedPositions)
            resolvedPositions[cmd.animationId] = absolute
            drawImageCmd(interpolated, resourceId: resourceId, dest: absolute)
        case .fill:  drawFillCmd(cmd, dest: …)
        case .view:  drawViewCmd(cmd, …)
        case .rtt:   break
        }
    }
}
If animationId has no match in _lastCmdList (new entity), the current frame's command is used as-is — no interpolation artifact.

Summary

Value-type commands

DrawCmd is a struct. The full frame intent is a plain array — serializable, diffable, SDL-independent.

Double-buffered lerp

Two snapshots decouple display refresh from the fixed game-logic tick rate; rendering always 100 ms behind to avoid extrapolation.

Parent-relative coords

parentAnimationId links commands in a coordinate hierarchy. The interpolator resolves absolute screen rects at draw time.

Resource ownership

All SDL textures live in RendererServer. The client holds opaque UInt64 IDs only. LRU eviction via tick counters.

Virtual filesystem

VirtualDrive.shared aggregates mounted directories under a unified vd:// namespace. First-match wins across packages.

IDataSource abstraction

AtlasLoader accepts any IDataSource, allowing CombinedDataSource to compose VD with other loaders transparently.

Font/glyph ownership

Server keeps Font (SDL + atlas) in _fontCache. Client holds FontResource (metrics + UID map). Glyphs flow as DrawCmd(.image(resourceId:)) — no new infrastructure.
