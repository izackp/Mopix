1. Overview

Rendering intent is separated from rendering execution. Each frame, game and UI code produces a flat list of DrawCmd structs describing what to draw. That list is sent to RendererServer, which owns the SDL renderer and decides how and when to put pixels on screen.

  • Smooth visuals at any frame rate. The server keeps the last two command lists and lerps between them, so the display runs at monitor refresh rate while game logic ticks at a fixed slower rate.
  • Determinism / rollback friendliness. Commands are plain value types — diffable, replayable, and snapshotable independently of SDL state.

2. Actors

RendererClient

Accumulates DrawCmd values in cmdList: [DrawCmd] during draw(). Holds an IRendererServer reference and dispatches commands at frame-end via an async Task.

Keeps two command-list snapshots (last and future) and interpolates between them at draw time for smooth motion regardless of logic tick rate.

FullWindow

The orchestrator. Calls clearCommands(), drives game/UI drawing, calls sendCommands(), then immediately calls drawingInterpolator.draw() to flush to screen.

3. DrawCmd

DrawCmd is the sole unit of communication — a plain struct with no references or SDL handles.

// BatchRenderer/DrawCmd.swift
public struct DrawCmd {
    public let animationId: UInt64       // identity key for lerp matching
    public let parentAnimationId: UInt64 // coordinate-space parent
    public let dest: Rect<Int>
    public let color: SDLColor
    public let alpha: Float
    public let z: Int                     // draw order
    public let rotation: Float
    public let rotationPoint: Point<Int>
    public let clippingRect: Rect<Int>
    public let flip: BitMaskOptionSet<Renderer.RendererFlip>
    public var time: UInt64              // timestamp used during lerp
    public let type: DrawCmdType
}
DrawCmdTypePayloadRenders
.image(resourceId:)UInt64 → ResourceStore keyTextured quad from atlas
.fill—Solid-color rectangle
.view(borderColor:borderWidth:)Border color + widthView background with optional border
.rtt—Render-to-texture (reserved)

lerp()

Only .image commands are interpolated. DrawCmd.lerp() blends two snapshots given a timestamp:

// DrawCmd.swift — simplified
func lerp(_ other: DrawCmd, time: UInt64) -> DrawCmd {
    let t = calcT(from: self.time, to: other.time, current: time)
    return DrawCmd(dest: lerp(self.dest, other.dest, t),
                    alpha: lerp(self.alpha, other.alpha, t), /* … */)
}

5. Async Send & Receive

IRendererServer defines the protocol boundary:

// IRendererServer.swift
protocol IRendererServer: AnyObject {
    func receiveCmds(_ list: [DrawCmd]) async
    // … resource loading / unloading methods …
}
// RendererClient.swift
public func sendCommands() {
    Task { await server.receiveCmds(self.cmdList) }  // fire-and-forget
}

// RendererServer.swift
func receiveCmds(_ list: [DrawCmd]) async {
    await MainActor.run { self.receiveCmdsSync(list) }
}

func receiveCmdsSync(_ list: [DrawCmd]) {
    resourceStore.increaseTicks()          // age all resource counters
    drawingInterpolator.receiveCmds(list)  // buffer swap
}
Fire-and-forget. The client does not await delivery. The server runs on the main actor, so in practice the batch is processed before the next frame's draw() under normal conditions.

6. Interpolation

DrawCmdInterpolator maintains four collections:

FieldTypeContents
_lastCmdListIndexedOrderedList<DrawCmd>Previous frame's image-only commands, indexed by animationId for O(1) lookup
_futureCmdListIndexedOrderedList<DrawCmd>Current frame's image commands
_lastAllCmds[DrawCmd]Previous frame's full command list
_futureAllCmds[DrawCmd]Current frame's full command list, sorted by z

Buffer swap — receiveCmds()

// DrawCmdInterpolator.swift:43–67 — simplified
func receiveCmds(_ list: [DrawCmd]) {
    let imageOnly = list.filter { $0.type.isImage() }

    _lastCmdList  = _futureCmdList                                       // rotate
    _lastAllCmds  = _futureAllCmds

    _futureCmdList = IndexedOrderedList(imageOnly, keyPath: \.animationId)
    _futureAllCmds = list.sorted { $0.z < $1.z }
}

Lerp draw — draw()

// DrawCmdInterpolator.swift:69–143 — simplified
func draw(_ time: UInt64) {
    var resolvedPositions: [UInt64: Rect<Int>] = [:]

    for cmd in _futureAllCmds {                            // sorted by z
        switch cmd.type {
        case .image(let resourceId):
            let previous    = _lastCmdList[cmd.animationId]
            let interpolated = previous.map { cmd.lerp($0, time: time) } ?? cmd
            let absolute     = resolvePosition(interpolated, resolvedPositions)
            resolvedPositions[cmd.animationId] = absolute.dest
            drawImageCmd(absolute, resourceId: resourceId)
        case .fill:  drawFillCmd(cmd)
        case .view:  drawViewCmd(cmd)
        case .rtt:   break  // reserved
        }
    }
}
If no matching animationId exists in _lastCmdList (newly spawned entity), the current frame's command is used as-is — no interpolation artifact.

7. Resource Lifecycle

Images are referenced in DrawCmd by a resourceId: UInt64. All texture memory lives in RendererServer — the client never touches SDL textures.

Loading

// Caller — async
let image = try await renderClient.loadImage(url: myVdUrl)
// image.resourceId is valid; embed in DrawCmd.type = .image(resourceId:)
  1. RendererClient.loadImage() calls await server.loadImage(url:).
  2. RendererServer asks ImageManager to decode and pack into the texture atlas.
  3. ResourceStore.registerAtlasImage() assigns a unique UInt64 ID and stores the AtlasImage.
  4. The ID is returned and embedded in subsequent DrawCmd values.

Unloading & LRU eviction

  • Explicit: renderClient.unloadResource(id) → async server.unloadResource(id).
  • Delayed: unloadResourceDelayed(id, ticks:) queues removal until the tick counter expires.
  • Tick aging: each receiveCmdsSync() call increments ticksSinceLastUse on every cached AtlasImage. fetchResource() resets it. cleanUnusedResources() evicts least-used entries when VRAM budget is exceeded.

8. UI Rendering Path

UI views do not call RendererClient directly. They receive a UICommandContext, which bridges the view tree into the same DrawCmd pipeline.

// FullWindow.swift — inside draw(time:)
let context = UICommandContext(
    client:       renderClient,  // IDraw — accumulates DrawCmds
    fontProvider: imageManager,  // IFontProvider — resolves TTF glyphs
    rttAllocator: renderServer   // IRTTAllocator — allocates atlas regions
)
try rootView.draw(context, rootView.frame)
MethodEmits
emit(_ cmd:)Forwards to client.drawCmd(cmd) (or RTT stack)
drawSquare(…)DrawCmd with type .fill
drawText(…)One DrawCmd(.image(resourceId:)) per glyph
createAndDrawToTexture(…)Allocates atlas region, renders into it, emits .rtt cmd
UIRenderContext is preserved. The original direct-SDL drawing class is kept alongside UICommandContext. When adding new draw paths, create a new class — do not modify UIRenderContext.

9. Summary

Value-type commands

DrawCmd is a struct. The full frame intent is a plain array — serializable, diffable, independent of SDL state.

Double-buffered lerp

Two command snapshots decouple display refresh from the fixed game-logic tick rate.

Parent-relative coords

parentAnimationId lets commands express position relative to another entity. The interpolator resolves to screen coords at draw time.

Resource ownership

All SDL textures live in the server. The client holds only opaque UInt64 IDs.
